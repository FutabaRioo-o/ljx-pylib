# 一体化上位机：按钮对应与测试说明

本文说明 `PC_MAIN_260811` 的硬件控制功能如何迁入现有网页
`一体化上位机界面V3.html`，以及在树莓派 + 平板 + PCB 同一 Wi-Fi
网络上的安全测试方法。

> **安全前提**：首次联调时，机械运动范围必须清空、双冲击枪应断开负载或
> 接到安全指示负载，并确认现场急停可用。不要保留示例脉冲、示例位置或
> 默认速度后直接运行设备。

## 1. 网络与程序架构

| 设备 | 地址/角色 | 说明 |
|---|---|---|
| 树莓派 | `192.168.4.1` | Wi-Fi 热点、网页服务、激光采集服务、PCB TCP 客户端 |
| 平板 | `192.168.4.100` | 连接树莓派 Wi-Fi，通过浏览器操作网页 |
| PCB | 同一 Wi-Fi 内的独立地址 | 必须在配置文件中填写实际 IP；程序不会猜测地址 |

平板只访问树莓派：

```text
http://192.168.4.1:8000
```

树莓派再通过 TCP 连接 PCB。旧 PC 程序截图中的 `192.168.10.100:1200`
不是树莓派或平板地址；其中端口 `1200` 被保留为旧 PCB 通讯的默认端口，
实际 PCB IP 必须现场确认。

```text
平板浏览器  -- HTTP/JSON -->  树莓派 HMI  -- TCP 16 字节帧 -->  PCB
                                      |
                                      +-- LJ-X8000A 激光采集
```

## 2. 启用 PCB 通讯前的配置

编辑 `integrated_hmi_config.json` 的 `main_controller`。示例中的 PCB 地址
仅为格式示意，不能照抄：

```json
"main_controller": {
  "enabled": true,
  "host": "192.168.4.2",
  "port": 1200,
  "mode": "client",
  "connect_timeout_seconds": 2.0,
  "protocol": "legacy-16-byte-aa-function-payload-ff"
}
```

首次部署时，仓库配置保持：

```json
"enabled": false,
"host": ""
```

这是故意的安全默认值：在不知道 PCB 地址时，网页不会连接或发送控制帧。

还必须按实机标定 `motion` 与 `workflow`：

| 配置项 | 含义 | 首次实机运行要求 |
|---|---|---|
| `a_position_scale` | 网页 A 轴单位到 PCB 位置量的换算 | 按实际减速比/编码器单位填写 |
| `b_steps_per_unit` | B 轴单位到脉冲的换算 | 按推杆行程标定 |
| `c_steps_per_unit` | C 轴单位到脉冲的换算 | 按推杆行程标定 |
| `b_default_speed` / `c_default_speed` | B/C 推杆默认速度 | 从厂家确认的低风险值开始 |
| `workflow.a_target_position` | 自动扫描 A 轴目标位置 | 首次应设为确认安全的值，而不是直接使用示例 `180` |
| `workflow.b_scan_steps` / `c_scan_steps` | 扫描前 B/C 相对脉冲 | 首次可设为 `0`，确认通讯后再逐步增加 |
| `workflow.b_stress_steps` / `c_stress_steps` | 应力消除前 B/C 相对脉冲 | 需按双枪工位标定 |

## 3. 旧 PC_MAIN 协议

帧格式保持兼容：

```text
AA + 功能码 + 参数（补零） + FF
总长度 16 字节
```

| 功能码 | 旧程序名称 | 参数/用途 | 现有实现 |
|---|---|---|---|
| `0x01` | `Func_UPDATA` | PCB 上报 Pitch、Roll、Yaw、电量 ADC | 接收、解码、显示 |
| `0xB1` | `Func_RELAY` | 继电器 1、继电器 2 开关 | 已实现 |
| `0xB2` | `Func_MOTO1` | 推杆电机 1：方向、脉冲、速度 | 已实现，映射 B 轴 |
| `0xB3` | `Func_MOTO2` | 推杆电机 2：方向、脉冲、速度 | 已实现，映射 C 轴 |
| `0xB4` | `Func_MOTORS` | RS485 电机位置 | 已实现，映射 A 轴 |
| `0xB5` | `Func_SPEEDRS` | RS485 电机速度 | 已实现为 2 字节大端速度值，**需实机验证** |
| `0xB6` | `Func_RUNRS` | RS485 电机停止/恢复 | 已实现停止；恢复尚无现有网页按钮 |

`0xB5` 是依据需求文档新增使用的功能码。旧 C# 项目定义了该常量，
但没有实际点击事件发送它；因此必须在空载、低风险速度下确认 PCB 固件
对该帧的长度、字节序和单位是否一致。

## 4. 按钮对应表

### 4.1 已一对一或等价对应的硬件控制

| 旧 PC_MAIN 按钮/事件 | 旧功能 | 现有 V3 页面按钮 | 当前动作 | 状态 |
|---|---|---|---|---|
| `btn_OpenSocket_Click` | 作为 TCP Client/Server 建立通讯 | “连接设备”“PCB 通信 → 测试连接” | 树莓派按配置作为 TCP Client 连接 PCB | 已对应 |
| `uiSymb_mul_Run1_Click` | 电机 1 正/反向、脉冲、速度 | “激光推杆电机 B”正向/反向点动 | 发送 `0xB2` | 已对应 |
| `uiSymb_mul_Run2_Click` | 电机 2 正/反向、脉冲、速度 | “矫顽力推杆电机 C”正向/反向点动 | 发送 `0xB3` | 已对应 |
| `uiSymb_RsRun_Click` | RS485 电机按位置正/反向运行 | “环向运动电机 A”正向/反向点动 | 发送 `0xB4` | 已对应 |
| 旧 C# 常量 `Func_SPEEDRS` | RS485 转速 | A 轴速度、自动扫描 A 轴速度 | 发送 `0xB5` | 已实现，需实机确认 |
| `uiSymb_RsStop_Click` | 停止 RS485 电机 | A 轴停止 | 发送 `0xB6=0` | 已对应 |
| `uiSymb_Relay_Click` | 同时下发两路继电器状态 | 冲击枪 A/B 对应的两个开关 | 发送完整 `0xB1` 两路状态 | 已对应 |
| PCB `0x01` 上传帧 | 姿态和电量显示 | 设备总览、IMU 卡片 | 显示 Pitch/Roll/Yaw/ADC | 已对应 |

### 4.2 现有网页的组合业务按钮

这些按钮不是旧 PC_MAIN 中的单个控件，但内部只组合调用上表的旧控制功能
和树莓派原有的激光功能。

| 现有 V3 页面按钮 | 运行顺序 | 使用的控制能力 |
|---|---|---|
| “开始自检” | 检查 PCB 是否已连接，再刷新激光状态 | TCP 连接状态、激光状态 |
| “开始扫描任务” | 等待 `t1` → B/C 定位 → 设置 A 轴速度 → A 轴到目标位置 → 启动激光连续采集 | `0xB2`、`0xB3`、`0xB5`、`0xB4`、树莓派激光服务 |
| “启动应力消除” | B/C 定位 → 开启继电器 1 和 2 | `0xB2`、`0xB3`、`0xB1` |
| “正常停止” | 取消待启动任务、停止 A 轴、关闭两路继电器、停止激光采集 | `0xB6=0`、`0xB1=00`、激光停止 |
| “急停” | 与正常停止使用相同的软件安全停机链路 | `0xB6=0`、`0xB1=00`、激光停止 |

> 网页“急停”是软件急停，不能取代独立的硬件安全急停回路。

### 4.3 没有可安全一对一映射的按钮

| 页面或旧版功能 | 当前处理 | 原因 |
|---|---|---|
| B 轴独立停止 | 显示提示，不发送帧 | 旧协议没有 B 轴独立停止功能码 |
| C 轴独立停止 | 显示提示，不发送帧 | 旧协议没有 C 轴独立停止功能码 |
| B/C 回原点 | 显示提示，不发送帧 | 旧协议没有回原点功能码或实际位置反馈 |
| A 轴设零 | 显示提示，不发送帧 | 旧协议没有设零功能码 |
| 旧版“恢复运行” | 尚未绑定网页按钮 | 旧版可发送 `0xB6=1`，但 V3 没有明确的“恢复”控件 |
| 旧版“关闭 Socket” | 后端有断开接口，未占用网页按钮 | 旧 C# 设计器有该按钮，但源码没有绑定点击事件 |
| 旧版“清空收发计数” | 后端有接口，未绑定网页按钮 | V3 页面没有对应的现有控件 |
| 旧版“握手”“查询”“下载参数” | 不发送硬件帧 | 旧 C# 代码本身已将发送逻辑注释或留空 |

## 5. 不接硬件的软件测试

在开发电脑或树莓派的 `ljx_pylib/PYTHON` 目录执行：

```bash
python3 -m unittest discover -s tests -v
node --check hmi_bridge.js
python3 -m py_compile integrated_config.py main_controller.py workflow_controller.py hmi_server.py
```

预期：所有 Python 测试通过，JavaScript 和 Python 语法检查没有输出错误。
当前测试覆盖：

- 16 字节旧协议帧布局；
- TCP 分片、粘包和噪声恢复；
- 姿态/电量解码；
- `0xB5` RS485 速度帧；
- B/C → A → 激光的扫描顺序；
- 应力消除先定位、后开双继电器；
- 停止按钮取消等待中的任务；
- 旧校准参数迁移与数学工具。

在 PCB 未配置时启动网页服务：

```bash
python3 hmi_server.py --host 0.0.0.0
```

然后在平板或本机浏览器打开：

```text
http://192.168.4.1:8000
```

此时点击“连接设备”或自动任务按钮应提示“PCB 通信未启用”，不会运动。
“正常停止”“急停”仍会停止树莓派侧可能存在的激光连续采集。

## 6. 上电前的 Wi-Fi 与 TCP 检查

1. 树莓派、平板、PCB 连接同一个树莓派 Wi-Fi。
2. 在树莓派确认自己的地址是 `192.168.4.1`。
3. 确认 PCB 地址，例如 `<PCB_IP>`。
4. 在树莓派执行：

```bash
ping -c 4 <PCB_IP>
```

5. 若已安装 `nc`，检查旧协议端口：

```bash
nc -vz <PCB_IP> 1200
```

`ping` 成功不代表 TCP 服务已启动；`nc` 成功才说明树莓派可连接到 PCB
对应端口。若 PCB 固件使用的不是 `1200`，必须同步修改配置文件端口。

## 7. 首次上电联调顺序

### 7.1 只验证通讯和上报

1. 保持 B/C 脉冲为 `0`，A 轴目标位置设为安全值。
2. 先不要点击任何运动或继电器按钮。
3. 设置 PCB 的真实 IP，保存配置，将 `enabled` 改为 `true`。
4. 重启 `hmi_server.py`。
5. 打开网页，点击“连接设备”。
6. 检查“PCB 通信”显示正常，并等待 IMU 的 Pitch/Roll/Yaw 与电量 ADC 更新。

若连接失败，先检查 Wi-Fi、PCB IP、端口、PCB TCP 服务模式和防火墙；不要
通过反复点击运动按钮排查通讯问题。

### 7.2 手动 B/C 推杆测试

1. 在 `motion` 中填写已确认的低风险 `b_default_speed`、`c_default_speed`。
2. 将 `b_steps_per_unit`、`c_steps_per_unit` 设为已标定值；未标定时不要运动。
3. B 轴、C 轴各用很小的相对行程，分别测试正向和反向。
4. 观察实际方向是否与网页方向一致；若反向，优先调整机械方向定义或换算约定，
   不要把“正向”按钮随意改成发送错误功能码。
5. 由于旧协议没有 B/C 停止和实际位置反馈，动作期间不得依赖网页“停止”来中断
   推杆；需要现场硬件安全措施。

### 7.3 A 轴与 `0xB5` 速度测试

1. 确认 A 轴无碰撞风险，先测试 `0xB4` 的很小位置变化。
2. 再用厂家确认的最低安全转速测试 `0xB5`。
3. 检查正反向、位置单位、速度单位和实际速度。
4. 若 A 轴不动、速度异常或通讯断开，立即使用硬件急停，并恢复
   `enabled: false`；记录 PCB 收到的帧后再确认固件协议。

### 7.4 继电器测试

1. 双枪必须处于安全负载状态，或先断开主功率回路。
2. 分别切换冲击枪 A/B 开关，确认继电器 1/2 指示状态。
3. 点击“正常停止”，确认两路继电器均关闭。
4. 点击“急停”，再次确认两路继电器关闭。

### 7.5 自动扫描与应力消除测试

1. 首先将 `workflow.b_scan_steps`、`c_scan_steps`、
   `b_stress_steps`、`c_stress_steps` 配置为 `0`。
2. 将 `workflow.a_target_position` 配为安全值，并确认激光连续采集可单独工作。
3. 点击“开始扫描任务”，确认状态顺序为：等待 → 定位 → 扫描中；并确认
   激光开始采集。
4. 点击“正常停止”，确认激光停止、A 轴停止、两路继电器关闭。
5. 在单轴低速测试通过后，再逐步增加 B/C 脉冲，最后测试双枪应力消除。

## 8. 常用接口（排障用）

| 方法 | 地址 | 用途 |
|---|---|---|
| `GET` | `/api/main-controller/config` | 查看树莓派读取到的安全公开配置 |
| `GET` | `/api/main-controller/status` | 查看 PCB 连接、收发字节、遥测、最近错误 |
| `POST` | `/api/main-controller/connect` | 建立到 PCB 的 TCP 连接 |
| `POST` | `/api/main-controller/disconnect` | 主动断开 PCB 连接 |
| `POST` | `/api/main-controller/safe-stop` | A 轴停止并关闭两路继电器 |
| `GET` | `/api/workflow` | 查看自动流程状态与估算位置 |
| `POST` | `/api/workflow/stop` | 取消自动任务、停止激光、执行安全停机 |
| `GET` | `/api/laser/status` | 查看激光状态 |

示例：在树莓派本机检查状态：

```bash
curl http://127.0.0.1:8000/api/main-controller/status
curl http://127.0.0.1:8000/api/workflow
```

## 9. 已知限制与后续协议建议

旧 PCB 协议无法报告 B/C 的真实位置、完成状态、限位状态，也无法独立停止或
回原点。因此网页的 B/C 位置只是在每次成功下发脉冲后累加的**软件估算值**，
不能作为安全位置反馈。

后续 PCB 固件协议建议补充：

1. B/C 独立停止；
2. B/C 回原点；
3. B/C 实际位置与限位开关上报；
4. 指令序号和执行完成应答；
5. 硬件急停状态上报；
6. `0xB5` 的速度单位、范围与字节序正式说明。

在这些协议明确前，自动流程只能在机械标定、低速试验和现场安全措施完善后使用。
